# 本地验证与发版

## 一条命令自动选择

```bash
cd /Users/guochenyuan/Desktop/高佳欣 && ./test_app.sh
```

已连接且授权的 Android 真机优先；没有真机时使用 Chrome。不会自动发布版本。

需要来回切换时使用菜单：

```bash
cd /Users/guochenyuan/Desktop/高佳欣 && ./test_app.sh menu
```

在运行中按 `q` 退出本轮，回到菜单再选择 Web 或手机。`r` 热重载、`R` 热重启。

| 命令（项目根目录执行） | 用途 |
| --- | --- |
| `./test_app.sh web` | Chrome 中验证页面、登录、业务逻辑 |
| `./test_app.sh phone` | 已连接 Android 手机运行调试版 |
| `./test_app.sh profile` | 真机性能模式；测性能用这个，不能用 debug 版时延做结论 |
| `./test_app.sh smoke` | 在真机自动安装并运行启动集成测试 |
| `./test_app.sh test` | 运行单元/组件测试 |
| `./test_app.sh auto --check` | 仅检查配置与自动设备选择，不构建、不安装 |
| `./test_app.sh phone --device <设备ID>` | 多台手机时指定目标 |

手机需要 USB 连接、开发者选项、USB 调试，并在手机上允许电脑授权。iPhone 不属于当前项目的已配置平台；Android 模拟器也不会被当作“已连接真机”自动选择。

Web 调试使用本地渲染资源（`--no-web-resources-cdn`），避免 Google CDN 无法访问导致白屏。Web 使用同一套 Supabase 业务代码，但不执行原生推送、Shorebird 补丁和 APK 安装更新。Web 构建只接收公开的 Supabase URL/客户端密钥，不包含蒲公英私有 API Key。浏览器验证不能替代手机网络、推送、安装更新和真实启动性能验证。

旧入口 `cd app && ./scripts/run_with_env.sh` 仍可用，已转向统一入口，也可以追加 `web`、`phone` 或 `menu`。

如果生成的构建缓存被云盘转为占位文件，入口会先将缓存转移到 `app/.workflow-cache-backups/` 再重新生成，避免读取旧缓存卡住；备份不提交 Git，已生成的常规 release APK 会保留。

## 原发布命令仍保留

```bash
cd /Users/guochenyuan/Desktop/高佳欣 && ./publish_new_version.sh 1.6.3 "全面优化"
```

这条命令会检查配置与蒲公英目标应用、运行测试、递增构建号、更新图标、构建 Android Release APK 并上传。`1.6.3` 允许重复使用，构建号会严格增加，因此能区分同一展示版本的不同构建。构建或上传失败会返回非零状态，不能当作发布完成。

先检查、不上传：

```bash
cd /Users/guochenyuan/Desktop/高佳欣 && ./publish_new_version.sh 1.6.3 "全面优化" --check
```

只构建、不上传：

```bash
cd /Users/guochenyuan/Desktop/高佳欣 && ./publish_new_version.sh 1.6.3 "全面优化" --build-only
```

`--check` 不改变版本，不生成安装包，也不发布；它会读取蒲公英现有应用信息以校验密钥和目标。`--build-only` 会更新本地版本并生成 APK。两个选项不能同时使用。

配置：客户端读取 `app/env.json`；自动上传读取根目录 `pgyer_config.sh` 中的 `PGYER_API_KEY`。这些文件都不提交 Git。安装包位于 `app/build/app/outputs/flutter-apk/app-release.apk`。

发布脚本已将旧的 `www.pgyer.com/apiv2/app/upload` 地址改为官方旧版上传地址 `upload.pgyer.com/apiv2/app/upload`，并使用 JSON 的 `code` 和下载链接判断结果。官方还提供三步快速上传流程，可在后续有需要时迁移：[蒲公英上传文档](https://www.pgyer.com/doc/view/api_upload)。
