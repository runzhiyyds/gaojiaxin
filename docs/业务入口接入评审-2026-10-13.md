# 业务入口接入评审（尚未启用）

## 当前状态与拟启用范围

线上 `https://gaojiaxin-check.pet-food-advisor.asia` 仅提供只读 `/health`，已在手机移动数据下验证。用户批准的范围是“仅新增这个子域名做检测”。本评审中的业务代码、配置和本地测试已准备，但未部署，客户端配置也未改变。

拟将这个精确主机名上的同一个 Worker 升级为业务入口，然后接入本地客户端进行真机验证。所有请求仍固定转发至原项目 `https://uebeyflmmpesjolcrhnp.supabase.co`；不迁移数据库，不变更情侣空间、心意值业务规则或 RLS。根域名、其他产品的 DNS/路由不纳入变更。

启用后，密码登录请求中的账号密码、公开客户端 API Key、会话 JWT 及业务请求会先经过用户控制的 Cloudflare Worker，再送给原 Supabase 项目。通信两段均使用 HTTPS，应用代码不记录请求或凭据，Worker observability 关闭，不存储服务端密钥。Cloudflare 作为新增的处理平台参与请求，因此必须先取得业务接入授权，不能沿用只读检测授权。

## 已准备的实现

- `src/gateway.js` 仅允许 Auth、REST/RPC、Storage、Realtime 前缀；拒绝 Auth admin、未支持路径与含糊的编码路径，不能指定其他上游。
- 原样传递客户端 API Key、用户 JWT、请求体、查询参数、上游状态与分页头。鉴权仍由 Supabase 执行，网关不会绕过 RLS，也不会生成高权限密钥。
- 登录和写入只转发一次；10 秒期限覆盖上游响应头和响应体，超时取消请求，不转交晚到响应。取消不能撤销上游已经提交的写入，失败后需读取最终状态再决定用户操作，不自动重放。
- 业务响应不缓存、不转发 Cookie；同项目重定向改为新入口。Realtime 升级只允许指定 WebSocket 路径。Storage 响应保持字节内容，但不会盲目重写业务 JSON 中的绝对 URL。
- 默认没有启用标记时业务路径返回 503；候选配置中的标记为启用，只有获准后才可部署该配置。现有只读配置继续使用 `src/index.js`。

17 项 Node 本地测试通过（只读 5 项、业务候选 12 项），覆盖不启用默认值、登录传递、REST/RPC、错误/超时不重试、晚到响应、响应体期限、CORS、路径限制、重定向、模拟 WebSocket 升级及 Storage 字节。Wrangler dry-run 打包通过。模拟测试不代表 Cloudflare 上真实 WebSocket、上传或真实账号登录已经验证。

## 获准后的客户端验证与回退

1. 升级同一个 Worker，前后确认只绑定 `gaojiaxin-check.pet-food-advisor.asia`；检查 `/health`、无效业务路径与没有凭据的鉴权响应，保留只读版本以便回退。
2. 客户端配置改为新入口，同时显式保留原本持久会话键 `sb-uebeyflmmpesjolcrhnp-auth-token`。Supabase Flutter 默认会话键包含 URL 的首段主机名，直接改域名会找不到旧会话；不能因此回退硬编码登录。
3. 验证移动数据下真实登录、退出/恢复会话、空间切换与心意值读写、RPC、Realtime 重连，以及 Wi-Fi/Web 回归。核对请求取消、账号/空间隔离与写入最终状态；Storage/绝对 URL 若实际使用，单独验证相关页面。
4. 只有业务验证通过后才发布客户端。回退时恢复客户端原服务 URL 和同一个持久会话键，Worker 恢复只读 `src/index.js` 版本；无需修改根域名或迁移数据库。原 URL 在当前移动网络仍可能不可达，回退不等于修复原路径。
