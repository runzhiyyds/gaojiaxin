# 离线“记一笔”真机验证（2026-11-01）

## 验证范围

- Android 真机：NOH-AN01（移动数据）
- 客户端：使用 `env.json` 构建并覆盖安装 Debug APK，保留原登录会话和本地数据
- 服务端：`record_point_offline` 事务 RPC；仅 `authenticated` 可执行，使用调用者权限并继续受 RLS 约束
- 离线队列：SQLite 持久化，业务内容使用 AES-256-GCM 加密；固定请求 ID 用于幂等提交

## 验证步骤与结果

1. 同时关闭 Wi-Fi 和移动数据，首页能够展示上次缓存的数据。
2. 离线进入“记一笔”，使用缓存的心意值项目填写并提交测试记录 `offline-test-1101`。
3. 客户端提示“此次记录已加密保存，联网后自动提交”，首页展示 1 条待同步记录。
4. 强制结束 APP 后，在仍离线的情况下重新启动，待同步记录仍存在，证明队列可以跨进程恢复。
5. 仅开启移动数据，队列自动进入后台提交；成功后待同步提示消失，双方心意值分别按主记录和随机奖励发生变化。
6. 再次强制结束并重启 APP，心意值未重复增加，待同步记录未重新出现。

## 服务端只读核对

以测试备注和 RPC 返回结果关联幂等请求，查询结果为：

```json
{
  "main_record_count": 1,
  "bonus_record_count": 1,
  "idempotency_request_count": 1
}
```

结论：断网提交、进程重启、恢复联网和再次重启的完整链路中，只产生了一次主记录、一次随机奖励和一次幂等请求，没有重复写入。

## 边界

- 当前仅“记一笔”支持离线提交；兑换、储值、编辑、删除仍要求在线完成。
- Android 不保证 APP 被系统或用户结束后仍有常驻进程。队列依靠本地持久化保证不丢失，并在 APP 再次启动、恢复前台、网络恢复或登录恢复时继续提交。
- 冲突不会自动覆盖服务端数据；记录会保留到成功提交或用户主动删除。
- 测试记录 `offline-test-1101` 当前保留在线上数据中，便于审计；如需删除，应单独确认主记录、随机奖励和可能的押金影响后处理。
